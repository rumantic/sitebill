## Основные типы полей

### primary_key
**Первичный ключ таблицы**

Уникальный идентификатор записи в таблице. Обычно auto_increment числовое поле.

**Использование**: ID записи (обязательное поле для каждой таблицы)

**Пример**: `data_id`, `user_id`, `order_id`

---

## Текстовые поля

### safe_string
**Строка (обычное текстовое поле)**

Текстовая строка произвольного содержания. Данные проходят фильтрацию для безопасности.

**Использование**: Имена, короткие тексты, заголовки

**Пример полей**: `name`, `email`, `title`, `address`

---

### textarea
**Многострочное текстовое поле**

Текстовый блок для ввода длинных текстов.

**Использование**: Описания, комментарии, длинные тексты

**Пример полей**: `description`, `comment`, `notes`

---

### textarea_editor
**Текстовое поле с визуальным редактором (WYSIWYG)**

Текстовый блок с возможностью HTML-форматирования. Включает визуальный редактор (обычно CKEditor).

**Использование**: HTML-контент, статьи, форматированные тексты

**Пример полей**: `content`, `article_text`, `description_full`

---

### password
**Поле для пароля**

Поле пароля с скрытым вводом символов. Значение автоматически хешируется при сохранении.

**Использование**: Пароли пользователей

**Пример полей**: `password`, `user_password`

---

## Скрытые и служебные поля

### hidden
**Скрытое поле**

Тип скрытого поля. Данное поле следует использовать, если содержимое этого поля важно, но вы не хотите чтобы его видели пользователи. 

**Использование**: Служебные данные, метки, UTM-метки

**Пример**: Создадим поле `utm_campaign` и будем туда передавать данные из переходов от поисковиков или различных рекламных кампаний. В строке запроса это поле будет, значит оно автоматически появится в форме. Но при этом do параметр нужно поставить `new_done`, чтобы элементы инициализировались из запроса.

**Пример полей**: `utm_source`, `utm_campaign`, `internal_marker`

## Поля выбора

### checkbox
**Галочка (да/нет)**

Тип наличия выбора, чекбокс с двумя состояниями: "выбрано" (1) и "не выбрано" (0).

**Использование**: Булевы значения, включение/выключение опций

**Пример полей**: `is_active`, `is_published`, `agree_terms`, `show_phone`

---

### select_box
**Выбор из статического списка**

Справочное значение. Хранит в себе ключ соответствующий одному из значений описанных как возможных вариантов этого поля.

**Настройка**: Набор опций выбора в формате пар `{key~~value}` - тут вам нужно вписать свои значения, которые будет видеть пользователь в форме.
- **Key** - будет храниться в базе
- **Value** - будет виден пользователям на сайте

**Пример конфигурации**:
```
{нет~~нет}{газ~~газ}{электро~~электро}
```

**Другой пример**:
```
{1~~Продажа}
{2~~Аренда}
{3~~Обмен}
```

**Использование**: Статические списки опций

**Пример полей**: `status`, `type`, `heating_type`, `priority`

---

### select_box_structure
**Выбор типа из списка (иерархический)**

Структурный элемент, иерархический. Применим только к списку разделов/типов из таблицы структуры.

**Использование**: Категории, рубрики, типы недвижимости

**Пример полей**: `topic_id`, `category_id`, `realty_type`

---

### select_by_query
**Выбор из списка записей из базы**

Справочное значение. Поле хранит в себе ключ некоего значения из внешней (связанной) таблицы.

**Настройка параметров связи**:
- `primary_key_table` - таблица, из которой берутся данные
- `primary_key_name` - поле-ключ в связанной таблице
- `value_name` - поле для отображения
- `query` - SQL-запрос для выборки данных
- `title_default` - текст нулевого элемента ("Выберите...")
- `value_default` - значение нулевого элемента (обычно 0)

**Дополнительные параметры** (в поле parameters):
- `autocomplete = 1` - Включение ввода значений с помощью плагина поиска по первым буквам autocomplete
- `disable_autocomplete_on_search = 1` - Отключаем опцию autocomplete в поисковых формах

**Пример настройки** (связь с таблицей городов):
```
primary_key_table: city
primary_key_name: city_id
value_name: name
query: SELECT * FROM site_city ORDER BY name
title_default: Выберите город
value_default: 0
```

**Использование**: Связь с другими таблицами, внешние ключи

**Пример полей**: `city_id`, `user_id`, `category_id`

---

### select_by_query_multi
**Выбор из списка записей из базы с множественным выбором**

Аналогичен `select_by_query`, но позволяет выбрать несколько значений одновременно. Данные хранятся в сериализованном виде.

**Использование**: Множественный выбор связанных записей

**Пример полей**: `tags`, `categories`, `features`

---

### select_entity
**Выбор сущности**

Специальный тип для выбора сущности из системы.

**Использование**: Системные связи с сущностями

## Файлы и изображения

### photo
**Фото (аватар)**

Поле хранения единичного изображения. Используется преимущественно для аватаров пользователей.

**Примечание**: Не используется и не поддерживается моделями, кроме модели user.

**Использование**: Аватары пользователей, фото профиля

**Пример полей**: `avatar`, `user_photo`

---

### uploads
**Загрузка фотографий (галерея)**

Коллекция медиаобъектов. Данный тип позволяет размещать на форме область для загрузки и прикрепления фотографий. 

**Хранение**: Если вы назовете поле `image`, тогда в таблице данного объекта будет создано поле `image` с типом `text`. Картинки хранятся там в виде названий файлов в сериализованном массиве. Сами файлы картинок хранятся в каталоге `/img/data/`

**Параметры** (в поле parameters):

| Параметр | Значение | Примечание |
|----------|----------|------------|
| `disableimagedesc` | 1 | Отключение поля ввода описания фотографии |
| `tagged` | 1 | Подключение тега |
| `max_img_count` | число | Максимальное число разрешенных к загрузке фото |
| `max_img_count_ext` | правило | Правила расширяющие параметр max_img_count |

**max_img_count_ext**: Указываются в виде строки `N:rule1:rule2`, где:
- N - числовое значение max_img_count
- rule1, rule2 - правила, при которых это значение вступает в действие

Правила указываются в виде `field,operand,value`, где:
- field - системное имя поля
- operand - условие сравнения (eq|neq|gt|lt)
- value - сравниваемое значение

**Использование**: Галереи фотографий, множественные изображения

**Пример полей**: `photos`, `gallery`, `images`

---

### docuploads
**Загрузка документов**

Коллекция медиаобъектов в виде присоединенных файлов (PDF, DOC, XLS и т.д.).

**Использование**: Прикрепление документов, файлов

**Пример полей**: `documents`, `files`, `attachments`

---

### attachment

Поле для прикрепления файлов любого типа.

**Использование**: Универсальные вложения

**Пример полей**: `attachment`, `file`

## Дата и время

### date
**Дата (DD.MM.YYYY)**

Поле хранения временных значений. Отображается в формате DD.MM.YYYY.

**Использование**: Даты событий

**Пример полей**: `birth_date`, `event_date`

---

### dtdatetime
**Дата и время (DD.MM.YYYY H:i:s)**

Поле хранения даты и времени в виде `YYYY-MM-DD HH:MM:SS`. Отображается с datetime picker.

**Использование**: Дата и время событий, создания записей

**Пример полей**: `created_at`, `updated_at`, `event_datetime`

---

### dtdate
**Дата (DD.MM.YYYY)**

Поле хранения даты в виде `YYYY-MM-DD 00:00:00`. Более современный вариант поля `date`.

**Использование**: Даты без времени

**Пример полей**: `start_date`, `end_date`, `deadline`

---

### dttime
**Время (H:i:s)**

Поле хранения времени в виде `0000-00-00 HH:MM:SS`.

**Использование**: Время без даты

**Пример полей**: `start_time`, `end_time`, `duration`

---

**Использование**: Геопозиции объектов

**Пример полей**: `coordinates`, `location`, `geo_position`

---

### tlocation
**Связанные списки географии**

Специальное поле для работы со связанными списками географии (Страна → Регион → Город).

**Использование**: Иерархическая география

**Пример полей**: `location`, `geo_data`

---

### gadres
**Адрес с геокодированием**

Поле адреса с возможностью геокодирования и интеграцией с картами.

**Использование**: Адреса с координатами

**Пример полей**: `address`, `full_address`

## Специальные типы

### structure
**Структура**

Специальный тип для работы со структурой сайта (категориями, разделами).

**Использование**: Привязка к структуре сайта

**Пример полей**: `structure_id`, `section_id`

---

### captcha
**Защитный код**

Поле для отображения CAPTCHA (защита от ботов). Не хранится в базе данных.

**Использование**: Защита форм от спама

**Примечание**: Обычно используется в публичных формах

---

### client_id
**Связь с таблицей клиентов**

Данный тип позволяет делать привязку к клиентам. Начальная функция CRM. 

**Описание**: Например, у вас некий клиент продает квартиру повторно или сдает несколько квартир. И чтобы не дублировать информацию об этом клиенте, мы создаем одну запись в таблице клиентов. И затем через поле `client_id` делаем привязку. 

**Удобство**: Реализуется через интерфейс поиска клиента по фамилии или по номеру телефона, прямо в форме ввода.

**Подробнее**: [Видео-урок по использованию и настройке](https://www.sitebill.ru/s/topic/3148/)

**Использование**: CRM-функционал, связь с клиентами

**Пример полей**: `client_id`, `owner_id`

---

### grade
**Оценка (рейтинг)**

Поле для выставления оценок или рейтинга (например, звёзды).

**Использование**: Рейтинги, оценки

**Пример полей**: `rating`, `stars`, `score`

---

### auto_add_value
**Автодобавляемое значение**

Значение, которое автоматически добавляется системой (например, текущая дата, ID пользователя).

**Использование**: Автоматические метки времени, автор записи

**Пример полей**: `created_by`, `added_date`

---

### separator
**Визуальный разделитель**

Не является полем данных. Используется только для визуального разделения секций на форме.

**Использование**: Организация структуры формы

**Примечание**: Не хранится в базе данных (dbtype = 'notable')

---

### injector
**Код из компонента**

Специальный тип для внедрения кода из внешнего компонента или кастомной логики.

**Использование**: Встраивание пользовательского кода, виджетов

**Примечание**: Не хранится в базе данных

---

### parameter
**Свободный ввод параметров (key=value)**

Коллекция данных-параметров в виде пар ключ-значение.

**Хранение**: По умолчанию данные хранятся в виде сериализованного массива. Для переключения способа хранения на JSON-строку используется параметр `type`.

**Параметры** (в поле parameters):

| Параметр | Значение | Примечание |
|----------|----------|------------|
| `type` | `json` | Тип хранимых данных (json вместо serialize) |

**Использование**: Дополнительные настройки, конфигурация

**Пример полей**: `settings`, `config`, `options`

---

### compose
**Объединение колонок и функций**

Это составной элемент. Используется только для отображения (нельзя редактировать напрямую значения, так как он состоит из значений других полей).

**Настройка** (в поле parameters):
- `columns` - список колонок через запятую
- `separator` - разделитель для склейки значений (по умолчанию `,`)
- `function` - название функции обработчика из hooks (опционально)

**Пример настройки** для колонки `address_composed`:
```
columns = city_id,district_id,street_id,number
separator = /
function = address_formatter
```

При выводе этого поля будет составлен набор из значений колонок city_id, district_id, street_id, number, разделённых символом `/`.

**Использование**: Вычисляемые поля, агрегация данных

**Примечание**: Только для чтения, не хранится в базе

---

### youtube
**Код видео Youtube**

Поле для ввода кода YouTube видео (ID или ссылки) с автоматическим встраиванием плеера.

**Использование**: Встраивание YouTube видео

**Пример полей**: `video`, `youtube_link`, `promo_video`

## Дополнительные параметры элементов

У каждого поля можно создавать дополнительные параметры в поле **parameters** (в формате `key=value`).

### Общие параметры

| Параметр | Значение | Описание |
|----------|----------|----------|
| `only_owner_access` | 1 | Если включить данную опцию для поля, тогда при генерации таблиц или выводе данных при просмотре объекта, данное поле будет иметь значение только, если его просматривает владелец данного объекта. Для всех остальных значение этого поля будет скрыто. |
| `readonly` | 1 | Поле только для чтения |
| `placeholder` | текст | Текст-подсказка внутри пустого поля |
| `class` | CSS-класс | Дополнительный CSS-класс для стилизации |
| `rows` | число | Количество строк для textarea |
| `cols` | число | Количество колонок для textarea |
| `maxlength` | число | Максимальная длина вводимого текста |
| `fxFlex` | число (0-100) | Ширина поля в процентах (для responsive дизайна) |
| `tab` | название | Имя вкладки, на которой будет размещено поле |

### Примеры использования параметров

**Текстовое поле с ограничениями**:
```
maxlength=255
placeholder=Введите ваше имя
class=form-control-lg
```

**Textarea с настройками**:
```
rows=10
cols=80
placeholder=Опишите проблему подробно
```

**Поле только для владельца**:
```
only_owner_access=1
```
